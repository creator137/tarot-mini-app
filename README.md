# Расклад онлайн | Карты таро

Telegram Mini App: Nuxt 4, Nuxt UI 4, PostgreSQL, DeepSeek, ЮKassa (только тестовые платежи).

## Локальный запуск

Требуется Node.js >= 24.15, npm и PostgreSQL 17. На Windows используйте `npm.cmd`, если PowerShell запрещает выполнение `npm.ps1`. В devDependencies также установлен локальный Node 24, используемый npm-скриптами.

```sh
npm ci
# Для нового окружения скопируйте .env.example в .env и заполните значения.
# Не перезаписывайте существующий .env.
docker compose up -d db
npm run db:migrate
npm run dev
# Во втором терминале:
npm run worker
```

Compose использует POSTGRES_PASSWORD из `.env`. DATABASE_URL должен содержать тот же пароль. Сервер БД доступен только через 127.0.0.1:5432. Для production используйте собственные секреты и резервное копирование.

В обычном браузере открывается **явно обозначенный демонстрационный режим**: примеры карт и текста, без списаний и вызова ИИ. В Telegram используется настоящая серверная авторизация; ошибки конфигурации не подменяются демо. Откройте http://localhost:3000 для проверки интерфейса.

## Продолжение работы на другом компьютере

В репозитории находятся исходники, все 78 изображений карт и рубашка в `public/cards/`, справочник, миграции, тесты и lock-файл зависимостей. Повторно скачивать изображения не требуется.

```sh
git clone https://github.com/creator137/tarot-mini-app.git
cd tarot-mini-app
npm ci
```

Создайте `.env` из `.env.example`, заполните настройки и выполните команды локального запуска выше. Секреты передавайте отдельно через защищённое хранилище; для новой локальной БД и сессий можно создать новые пароли и секреты. `.env`, `node_modules`, сборка, логи и содержимое PostgreSQL в Git не входят. Новая локальная база создаётся пустой; если нужна прежняя история и балансы, их необходимо перенести отдельной резервной копией PostgreSQL.

Для запуска внутри Telegram потребуется доступный HTTPS-адрес нового компьютера или сервера. Обновите `APP_URL`, перезапустите приложение и worker, затем настройте меню и webhook командой ниже. Старый временный туннель после остановки недоступен.

## Настройки

| Переменная | Назначение |
|---|---|
| BOT_TOKEN | Токен Telegram-бота, только сервер |
| SESSION_SECRET | Случайный секрет минимум 32 символа |
| DATABASE_URL | Строка подключения к PostgreSQL |
| POSTGRES_PASSWORD | Пароль локального контейнера PostgreSQL |
| APP_URL | Точный origin приложения; для Telegram публичный HTTPS |
| TELEGRAM_WEBHOOK_SECRET | Отдельный случайный секрет webhook |
| DEEPSEEK_API_KEY | Ключ DeepSeek |
| DEEPSEEK_MODEL | По умолчанию deepseek-flash |
| YOOKASSA_SHOP_ID | ID тестового магазина ЮKassa |
| YOOKASSA_SECRET_KEY | Тестовый ключ, начинающийся с test_ |
| PAYMENTS_ENABLED | false по умолчанию; true разрешает только тестовую ЮKassa |

`.env` игнорируется Git. Настоящие платежи запрещены в коде: live-ключ отвергается, ответы провайдера без `test: true` не зачисляются. Включение production-платежей потребует отдельного задания, изменения защит и настройки чеков по схеме продавца.

Для Telegram после размещения приложения на собственном HTTPS-домене:

```sh
node --env-file=.env scripts/configure-bot.mjs
```

Команда меняет меню и webhook бота; не запускайте её до готовности URL. В локальной реализации она автоматически не выполняется. В тестовом магазине ЮKassa задайте webhook `https://ваш-домен/api/webhooks/yookassa` для `payment.succeeded` и `payment.canceled`.

## Сборка и проверки

```sh
npm run typecheck
npm test
npm run cards:validate
npm run test:postgres
npm run build
npm run test:e2e
npm run preview
# При работающем локальном preview:
npm run test:browser
```

`test:postgres` проверяет конкурентные транзакции в отдельной временной схеме настоящего PostgreSQL. `test:e2e` поднимает отдельные приложение и worker, проверяет HTTP API и БД; внешние платёжный и ИИ-провайдеры в этом тесте заменены локальными fixtures. Это **не проверка реального DeepSeek или магазина ЮKassa**. Обе проверки удаляют только созданную ими временную схему `qa_<uuid>`.

`test:browser` использует установленный Chrome через Playwright, проверяет интерфейс и сохраняет снимки в игнорируемый `artifacts/`. Для другого расположения браузера задайте CHROME_PATH, для другого адреса — PREVIEW_URL.

## Учёт денег и генерация

- Цена определяется сервером: 5000/10000 копеек.
- Начало расклада блокирует кошелёк, проверяет доступный остаток, сохраняет карты и резерв в одной транзакции.
- `(user_id, request_key)` уникален; повтор покупки возвращает тот же заказ. Изменённое содержимое с тем же ключом отвергается.
- Worker забирает задачи через `FOR UPDATE SKIP LOCKED`. Lease защищает от позднего завершения старой попытки.
- DeepSeek вызывается вне транзакции. Результат проверяется по структуре, количеству и ID карт.
- Успех атомарно сохраняет ответ и списывает резерв. После трёх неудачных попыток резерв освобождается.
- Перезапуск worker восстанавливает истёкшие lease; повторный запрос к ИИ после аварии возможен, повторное списание пользователю — нет.
- ЮKassa использует стабильный Idempotence-Key. Webhook сверяется с авторизованным GET к провайдеру; проверяются ID, metadata, сумма, валюта, тестовый режим.
- Worker периодически сверяет незавершённые платежи. Повторные уведомления не пополняют баланс дважды.
- Сетевые вызовы ИИ и ЮKassa имеют тайм-ауты; серверные ошибки возвращаются без секретов и содержимого вопросов.

## Перед публичным запуском

Нужны реальный HTTPS-домен и размещение Node-приложения/worker, секреты DeepSeek и тестового магазина ЮKassa для проверки провайдеров, реквизиты продавца, контакты поддержки, окончательные условия услуги/приватности и фискальная схема. Требуются тесты на физических Telegram iOS/Android и проверка резервного копирования/восстановления production-БД. Ограничения Telegram по продаже цифровых услуг отдельно зафиксированы в PROJECT_DECISIONS.md; внешнее размещение backend само по себе не подтверждает исключение.

Публичное размещение и реальные платежи автоматически не включаются.
